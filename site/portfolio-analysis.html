What was combined

Four different seams, not four synonyms for “test”.

Coverage × execution cost

First preserve quality. Then optimize cost.

Mutation score is the gate. Runtime is a tie-breaker only among portfolios that reach the same 20/20 ceiling.

Selected 100% detection Detection loss

Lower runtime is better. Higher mutation detection is better. The selected portfolio is the left-most point on the 100% detection line under the current benchmark protocol.

Why the winner works

Move backend confidence out of the browser.

E2E API kills domain and API mutations through the real public boundary. Playwright then spends its cost only on browser-exclusive failures. The portfolio keeps 20/20 detection without paying UI cost for every lower-level rule.

Why UI-only loses

100% coverage can still be inefficient.

E2E UI only also killed 20/20 mutants, but its same-run median was 3.64 s versus 2.50 s for E2E API + E2E UI — a 31.4% median reduction with the same mutation ceiling.

Why backend-only loses

Fast is not enough if risk disappears.

The strongest backend-only portfolios stopped at 10/20. Ten browser-specific mutants survived, so their lower runtime cannot make them candidates for the final architecture.

Decision protocol

The winner was chosen by a rule defined before looking at the ranking.

This prevents a fast but weak portfolio from being declared “better” simply because it costs less.

  1. 1. Maximize realistic-mutant detection.Any portfolio below 20/20 is eliminated, regardless of speed.
  2. 2. Keep benign controls stable.Both semantically harmless controls must survive so brittle tests are not rewarded.
  3. 3. Compare equal-quality candidates on one runner.One warmup + five measured rounds, with rotating portfolio order, in the same GitHub Actions job.
  4. 4. Choose the lowest median.E2E API + E2E UI had the lowest same-run median among the eight 100%-detection portfolios.
Interpretation boundary

The winner is the best portfolio under this repository, mutant panel, runner, and protocol. Its median advantage over Unit + Integration + E2E UI is only about 1.3%, and the measured ranges overlap. That small gap should be re-measured with more iterations before claiming a universal performance law. The much larger UI-only penalty is the stronger architectural signal.
